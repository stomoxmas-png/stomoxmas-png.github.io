# CLAUDE.md — たけクイズ

## プロジェクト概要

子ども（想定学年：小学校高学年 5〜6年）がスマホでゲーム感覚で学べるクイズアプリ。
科目（国語・算数・理科・社会・英語・道徳）→ジャンル（例：国語なら漢字・慣用句・ことわざ・文章）の2段階で選び、ランダム出題される5問に答える。

GitHub Pages で公開する個人プロジェクト。

## 技術スタック

- 素のHTML / CSS / JavaScript のみ。ビルドツール・フレームワーク・npmパッケージは導入しない
- 外部CDNのライブラリにも依存しない（オフラインでも壊れず動くようにするため）
- ブラウザの標準API（`fetch`, `localStorage` 等）だけで完結させる

## ディレクトリ構成

```
index.html         トップ（科目選択→ジャンル選択→クイズ→結果を1ページ内で切り替え）
css/style.css       スタイル（モバイルファースト）
js/storage.js       localStorage 読み書き（ジャンルごとの成績）
js/quiz-engine.js   出題（ランダムに指定数を抽出）・採点ロジック
js/sound.js         効果音（Web Audio APIでその場生成、音声ファイルなし）
js/main.js          画面遷移・DOM描画・イベント処理
data/subjects.json  科目→ジャンル一覧のメタデータ
data/<科目>/<ジャンル>.json  各ジャンルの問題データ
```

## ジャンルの追加・削除手順（最重要）

ジャンル構成は今後どんどん変わっていく前提。以下の2ステップだけで完結する：

1. `data/subjects.json` の該当科目の配列にジャンル名を追記（削除する場合は配列から取り除く）
2. `data/<科目>/<ジャンル名>.json` を下記スキーマで作成（削除する場合はファイルも削除してよい）

科目そのものを増やす場合も `subjects.json` にキーを追加し、対応するディレクトリとJSONファイルを用意するだけでよい。コード側の変更は不要。

## 問題データのスキーマ

```json
{
  "passage": "（文章問題のときだけ使う本文。それ以外は省略可）",
  "image": "（国旗クイズなど画像を見せたいときだけ使う画像パス。それ以外は省略可）",
  "symbol": "（元素記号クイズなど、大きな文字だけ見せたいときに使うテキスト。それ以外は省略可）",
  "question": "設問文",
  "choices": ["選択肢1", "選択肢2", "選択肢3"],
  "answer": 0,
  "explanation": "答えを見るときに表示する解説文"
}
```

- `choices` は2〜5個の範囲で問題ごとに自由に変えてよい（クイズエンジンは要素数に応じて動的に描画する。ただし実際の出題時は正解を含めて最大3択に絞られる）
- `answer` は正解の `choices` インデックス（0始まり）
- `explanation` は「答えを見る」を押した後に必ず表示される。空文字にはせず、簡潔でよいので必ず書く
- `image` を指定すると、問題文の上に画像（`data/`と同階層の`images/`以下などに配置）を表示する。国旗当てクイズのように「見て答える」問題で使う
- `symbol` を指定すると、問題文の上に大きな太字のテキストを表示する。元素記号当てクイズ（`Fe` など）のように、画像ではなくテキストを大きく見せたい問題で使う
- 「正解以外はどれでもいい」問題（単語の意味当てなど）は `choices`/`answer` の代わりに `answerText` と `distractorPool`（正解以外の候補一覧）、任意で `choiceCount`（既定3）を使うと、遊ぶたびにランダムな組み合わせで出題される

## 出題・画面遷移の仕様

- 表紙（科目選択画面）には科目一覧のほか「科目おまかせ」（ランダムに1科目を選びジャンル選択画面へ遷移）と「ランダム」（全科目・全ジャンル混合で5問出題）ボタンがある
- ジャンル選択画面にはジャンル一覧のほか「ジャンルおまかせ」（ランダムに1ジャンルを選び、そのジャンルだけの通常のクイズを開始）と「◯◯のランダム」（その科目の全ジャンル混合で出題）ボタンがある
- ジャンル選択画面では、ジャンルボタン／「ジャンルおまかせ」／「◯◯のランダム」ボタンを押す前に出題数（3・5・10問、既定5問）を選べる。対象ジャンルの問題数がそれ未満の場合はある分だけ出題される
- ジャンルを選ぶと、そのジャンルのJSONからランダムに重複なく選んだ問題数だけ抽出して1セットとする（再挑戦のたびに組み合わせは変わる）
- 1画面1問。「選択肢をタップ→答えを見る→（正解・解説が表示される）→次へ」の流れ
- 「答えを見る」を押すまでは選択肢を選び直せる。押した後は選択・正誤が確定する
- 「戻る」を押すと1問前に戻り、そのときの選択状態・解答表示状態をそのまま復元する（前の問題を無理やり再回答させない）
- 最後の問題で「次へ」（表示上は「けっかを見る」）を押すと結果画面に遷移する

## 進捗・スコアの保存

- `localStorage` に科目・ジャンルごとの成績を保存する（`js/storage.js` 参照）
- キーは `takequiz:<科目>:<ジャンル>` の形式
- 保存内容：挑戦回数（`plays`）、ベストスコア（`bestScore`、0〜100点の得点）、出題数タイア（3・5・10問）ごとのベストタイム（`bestTimes`、ミリ秒）
- 出題数が3〜10問と可変なため、正解数ではなく `floor(正解数 / 出題数 * 100)` の点数で比較・保存する
- タイムは出題数によってかかる時間が変わるため、3・5・10問それぞれ別に自己ベストを記録する。結果画面には今回のタイムを、ジャンル選択画面の一覧には保存済みのベストタイムを表示する
- サーバー側での保存は行わない（この端末・このブラウザだけの記録でよい）

## UI方針

- スマホ縦持ちでの利用を前提に、タップ領域は大きく・余白は広めに取る
- テキストは短く、子どもが読みやすい言葉を使う
- 正解・不正解は色とアイコン的な強調で直感的に分かるようにする（`.correct` / `.wrong` クラス）
- 選択肢数（2〜5個）が変わってもレイアウトが崩れないようにする
- 効果音（選択・正解・不正解）は音声ファイルを使わず、`js/sound.js` の Web Audio API でその場生成する

## 動作確認方法

`fetch` で `data/` のJSONを読み込むため、`index.html` を `file://` で直接開くとCORSエラーになり動作しない。必ず簡易HTTPサーバー経由で確認する。

```bash
python3 -m http.server 8000
```

## コンテンツ作成方針

- 難易度の基準は小学校高学年（5〜6年）
- 現状 `data/` 配下の問題文・解説は「【仮問題】」「（仮）」を含むプレースホルダー。実際の問題文・選択肢・解説は別途作成して差し替える
- 新しいジャンルを追加する際も、まず上記スキーマ通りの仮データで骨組みを作り、動作確認してから中身の問題を作り込んでよい
